Why is coresymbolicationd using so much disk space?

If your Mac's disk filled up and you traced it to ~/Library/Caches/com.apple.coresymbolicationd, you're not alone. On a developer's Mac this one folder can quietly grow to 50, 80, even 100 GB or more.

What it is

coresymbolicationd is a macOS system daemon. It caches debug symbols so crash reports, stack traces and profiling tools can turn memory addresses back into function names. That process is called symbolication.

Why it grows

It adds to the cache every time you build in Xcode, attach a debugger or symbolicate a crash log. Apple never expires the cache, so it doesn't shrink on its own. It just keeps growing until you notice your disk is full.

Only macOS has this daemon, so this is a Mac developer problem. Windows and Linux don't build up anything like it.

Is it safe to delete?

Yes. It's a cache, and it rebuilds automatically. The only cost is that symbolication may be a little slower the first few times afterward, while the cache fills back in. Your code, projects and Xcode settings aren't stored there.

How to check its size

In Terminal:

du -sh ~/Library/Caches/com.apple.coresymbolicationd

How to clear it by hand

  1. Quit Xcode and Instruments.
  2. In Finder, choose Go → Go to Folder and enter ~/Library/Caches/com.apple.coresymbolicationd.
  3. Select everything inside the folder and move it to the Trash. Leave the folder itself in place.
  4. Empty the Trash to get the space back.

Or in Terminal, which deletes the folder's contents immediately and skips the Trash:

rm -rf ~/Library/Caches/com.apple.coresymbolicationd/*

Either way, it starts growing again the next time you build or debug.
